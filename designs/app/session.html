积分模块接口

基础路径 /api/points，鉴权走网关统一的 Bearer。所有写接口都要带 X-Request-Id，同一个请求号只处理一次。

兑换优惠券

POST /redeem：扣积分并发券。重复提交时返回第一次的结果。

字段类型说明
user_idint用户
coupon_idint优惠券
pointsint扣减积分，必须大于 0
curl -X POST /api/points/redeem \
  -H "X-Request-Id: r-1024" \
  -d '{"user_id": 1, "coupon_id": 7, "points": 500}'

错误码

  • 40901：积分不足
  • 40902：优惠券已领完
  • 42900：请求过快，稍后再试

import functoolsfrom datetime import timedeltafrom .cache import redis_clientTTL = timedelta(hours=24)def idempotent(handler):    """同一个请求号只处理一次，重复提交返回第一次的结果。"""    @functools.wraps(handler)    def wrapper(request, *args, **kwargs):        key = f"idem:{request.request_id}"        # 占位成功才执行，失败说明已经有人在处理        if not redis_client.set(key, "pending", nx=True, ex=TTL):            return redis_client.get(key)        result = handler(request, *args, **kwargs)        redis_client.set(key, result, ex=TTL)        return result    return wrapper

R-1024 积分兑换优惠券

需求说明：用户在积分商城用积分兑换优惠券。网络抖动或用户重复点击时，同一笔兑换不能扣两次积分。

验收标准：同一个请求号在 24 小时内只处理一次；重复请求返回第一次的结果；不同请求号互不影响。

R-1031 兑换失败时的积分返还

兑换失败（发券超时、库存不足）时，已扣的积分要在 5 分钟内自动返还，并给用户发站内信。

验收标准

  • 发券接口返回失败时，积分立即返还
  • 发券超时时，先查询结果再决定是否返还
  • 同一笔兑换只返还一次
