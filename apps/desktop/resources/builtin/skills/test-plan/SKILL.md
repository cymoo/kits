# 整理测试用例

## 步骤

1. 弄清楚测试对象：需求文档、接口说明、附件、`@` 引用的文件或代码改动。信息不够、猜错代价大时用 ask_user 问（比如环境、数据量、兼容哪些版本）；不影响大局的写成假设继续。
2. 读相关代码，找到真实的入参校验、分支和错误码，用例要和实现对得上；文档和代码不一致的地方单独列出来。
3. 按这些维度列用例：
   - 正常流程：主路径和常见的变体；
   - 边界值：空、最大最小、刚好越界、重复提交、并发；
   - 异常：依赖失败、超时、权限不足、数据不存在、状态不对；
   - 兼容：老数据、老客户端、开关打开和关闭。
4. 能执行的检查（单测、接口调用）可以跑一下确认现状，结果写进备注。

## 输出

用表格，每条一行：

| 编号 | 模块 | 场景 | 前置条件 | 步骤 | 预期结果 | 优先级 |

优先级用 P0（主流程、必须测）、P1（重要分支）、P2（低频边界）。表格后面单独列：文档和实现不一致的地方、做了哪些假设、还需要谁确认什么。
