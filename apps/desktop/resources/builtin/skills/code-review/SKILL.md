# 审改动

只读，不改文件、不提交。

## 步骤

1. 弄清楚要审什么：用户没说就审工作区未提交的改动（`git diff` 和 `git diff --staged`）；说了提交或分支就用 `git diff <基准>...<目标>`。
2. 先看改动涉及哪些文件、各自是什么作用，再逐个文件读 diff。diff 看不明白的地方，读改动前后的完整函数。
3. 重点找这些问题：
   - 逻辑错误、边界条件（空值、空列表、并发、超时、重试）、错误处理被吞掉；
   - 改了接口或数据结构但调用方、测试、文档没跟着改；
   - 缺测试：改动的分支有没有测试覆盖，测试有没有真的断言到行为；
   - 安全：拼接 SQL / 命令、未校验的外部输入、密钥写进代码或日志。
4. 能跑测试就跑一下相关的测试，用结果佐证判断；跑不了就说明。

## 输出

按“严重 / 一般 / 建议”分组，每条写：

- 位置（文件:行）
- 问题是什么、会导致什么后果（给一个具体的输入或场景）
- 怎么改（一两句，必要时给代码片段）

没发现问题就直说，并写清楚看了哪些文件、跑了哪些测试。不要为了凑数列风格问题。
