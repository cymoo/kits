# 交付说明

验收的人只看这份文档，不通读代码。文档写不清楚的，视为没交付。

## 步骤

1. 定模块名：用提交信息里的 scope（`session`、`kernel`、`mcp`、`skills`、`workbench`、`settings`、`storage` …）。文件是 `docs/delivery/<模块>.md`。
2. 文件已存在就在末尾追加一节 `## <日期> <一句话>`，不存在就按 [docs/delivery/TEMPLATE.md](../../../docs/delivery/TEMPLATE.md) 新建。
3. 按模板逐节填：
   - **原始需求**：这次要解决什么，引用 issue 和原型页面（`designs/app/xxx.html`）。写清楚做到什么程度算完。
   - **怎么验收**：一步一步，每步写操作和预期结果。验收用的数据（需求文本、mock 事件流、用例文件）放到 `evals/samples/` 或测试目录里，并写明路径。
   - **主要改动**：改了哪些模块；新增或修改的配置项；数据库 schema 有没有变、迁移文件在哪；原型没画到、按风格补的地方。
   - **测试**：单测覆盖了什么、E2E 覆盖了哪条流程、怎么跑。
   - **新增依赖**：名称、版本、用途、许可证。没有就写“无”。
   - **已知问题**：没做完的、绕过的、手改过 AI 代码的地方和原因。
4. 自己照“怎么验收”走一遍，走不通就改文档或改代码。

## 写法

- 中文，写结论和理由，不写过程。
- 步骤要能照着做：有命令就给完整命令，有界面操作就写到按钮名。
- 不要写“见代码”“参考实现”，验收的人不看代码。
