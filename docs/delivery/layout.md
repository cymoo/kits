# 交付说明：layout

## 2026-11-04　拖动改变侧栏和工作区面板的宽度

> 日期：2026-11-04　PR：见本分支 `feat/shell-resizable-panels`　作者：Claude Code

### 原始需求

用户问“是否有必要支持左右侧栏拖动改变宽度”。结论是做：右侧面板要看 diff 和命令输出，固定 380px 经常截断；左侧栏的会话标题也有同样的问题。这也是同类桌面工具的默认能力，实现不需要新依赖。

原型：[designs/app/shell.js](../../designs/app/shell.js)（手柄 `.k-rz`）、[session.html](../../designs/app/session.html)。

### 怎么验收

1. 鼠标移到左侧栏右边缘，光标变成左右拖动，边缘出现蓝线。拖动，侧栏跟手变宽，范围 200～360px。
2. 会话页拖动右侧面板的左边缘，范围 300～720px。⌘\ 放大工作区后，拖动的是左边对话栏，范围 320～640px。
3. 关掉应用再打开，三个宽度都还在。
4. 双击手柄，恢复默认（248 / 380 / 400px）。
5. Tab 移到手柄上，← → 每次调 16px。
6. 把右侧面板拖到最宽，再把窗口缩到 900px：对话栏至少留 320px，放大工作区时右边至少留 360px；窗口拉大后恢复记住的宽度。
7. 拖动侧栏时不松手，按 ⌘B 收起侧栏，再松手：光标恢复正常，页面文字能选中，收展动画还在。

### 主要改动

- `lib/widths.ts`（新增）：三栏的上下限和默认值，读存储时校验。
- `lib/ui-store.ts`：`widths` 和 `setWidth`，存 localStorage 的 `kits.widths`，和侧栏折叠、面板大小一样按设备记，不进 `settings.json`。
- `ui/ResizeHandle.tsx`（新增）：拖动、双击恢复、键盘调整，`role="separator"`。自身宽度为 0，不占位置。拖动从栏的实际宽度算起，窗口窄时不会有一段拖了没反应。拖动中手柄被卸载时也会清掉全局的拖动状态。
- `Layout`、`Nav`、`SessionPage`：接上手柄，宽度改成 `style`。
- 窗口窄时用 CSS 的 `max-width` 让位，不改记住的值：侧栏不超过窗口 40%，右侧面板给对话留 320px。这也解决了 900px 窗口下对话栏只剩约 270px 的问题。
- 配置项、数据库 schema 都没变。

### 测试

- 单元测试：`widths.test.ts`，上下限、取整、坏数据回退默认。
- E2E：`shell.spec.ts` 拖动、键盘、重开后还在、双击恢复、拖到一半收起侧栏后清掉拖动状态；`workbench.spec.ts` 右侧面板和放大时的对话栏。

### 新增依赖

无。

### 已知问题

- 放大工作区时改动面板里的文件列表（280px）还不能拖。
- 宽度只按设备记在 localStorage，不跟随配置目录。

## 2026-11-05　停止按钮放进输入框，消息不超宽，输出时不跳

> 日期：2026-11-05　PR：见本分支 `feat/session-stop-in-composer`　作者：Claude Code

### 原始需求

内网用户反馈：

- 会话停止按钮在右上角，不明显，改到对话框更方便。
- 用户消息自适应宽度时超出边界。
- 输出内容时 UI 组件跳动。

评审结论：

- 停止和发送共用一个按钮：运行中输入框是空的时是停止，有内容时是发送（这一轮结束后送出）。去掉顶栏的停止按钮，快捷键不变。
- 运行中模型说的话都放在工作过程卡片里，这一轮结束后最终回复才放到卡片下方。运行中不搬动，结束时变动一次。

原型：[designs/app/session.html](../../designs/app/session.html)、[shell.js](../../designs/app/shell.js)，看 `session.html?s=permission`。

### 怎么验收

1. `KITS_KERNEL=mock KITS_MOCK_SCENARIO=streaming KITS_MOCK_SPEED=3 pnpm dev`，发任意任务。预期：顶栏没有停止按钮，输入框右下角是方块停止键，提示“停止”和快捷键。
2. 运行中在输入框打字。预期：按钮变成发送箭头。清空文字后变回停止，点它，状态是“已停止”，按钮变回发送。
3. 再发一条，按 ⌘.（Windows 是 Ctrl+.）。预期：同样停止。
4. 发一条很长的、不带空格的路径。预期：消息在气泡里换行，不超出对话区，没有横向滚动。
5. 用默认速度发一条，盯着正文。预期：文字在“第 1 轮”卡片里输出，不会突然被收走；下方状态行一直在，只换文字。这一轮结束时卡片收起，最终回复出现在卡片下方，带复制按钮。
6. 对话内容刚好超出一屏时看正文宽度。预期：滚动条出现时文字不重新换行。

### 主要改动

- `shell/Composer.tsx`：新增 `onStop`，传了且没有内容时显示停止键。`pages/session/SessionPage.tsx`：去掉顶栏按钮，运行中传 `onStop`；对话区加 `scrollbar-gutter: stable`，一直留出滚动条的位置。
- `session/thread/derive.ts`：运行中文字生成 `live` 步骤，不再分出 `text` 块，`text` 块去掉 `streaming`；状态行在运行中一直存在，有新内容时写“正在回复”。
- `session/thread/Blocks.tsx`：卡片里用 Markdown 显示 `live` 步骤；用户消息和附件名按 `overflow-wrap: anywhere` 换行；状态行 2 秒内不显示计时。
- 原型：`session.html`、`shell.js` 同步改；`runtime.js` 把模板变量传给共用组件，输入框才能知道是否在运行。

配置项、数据库 schema 没有变化。

### 测试

- 单元测试：`thread/derive.test.ts` 覆盖工具开始时文字不搬动、状态行一直在。
- E2E：`session-stream.spec.ts` 新增输入框停止和发送切换、超长消息不溢出、运行中文字在卡片内并在结束后移到下方。

### 新增依赖

无。

### 已知问题

- 有草稿时界面上没有停止键，只能用快捷键或先清空。这是共用一个按钮的取舍。
- 一轮结束时卡片收起、回复移到下方，这一下位置会变。
- 没有工具调用的简单问答，运行中也显示在卡片里，结束后卡片消失。
- 反馈没有说明具体是哪个组件在跳，这里修的是代码里找到的来源：文字被收走、状态行增减、滚动条占位。没有在 Windows 上实看。

## 2026-11-05　运行中有文字时，按钮提示改成“排队发送”

> 日期：2026-11-05　PR：见本分支 `fix/session-queue-tooltip`　作者：Claude Code

### 原始需求

运行中输入框有文字时，按钮提示写的是“发送”，实际是排到这一轮结束后才发，容易误解。

### 怎么验收

1. 空闲时在输入框打字，鼠标移到按钮上。预期：提示是“发送 ↵”。
2. 发一条让 Agent 运行，再在输入框打字。预期：提示是“排队发送 ↵”，图标还是箭头。
3. 点按钮。预期：消息出现在“这一轮结束后发送”的排队区。

### 主要改动

- `shell/Composer.tsx`：运行中按钮的提示和无障碍名称改成“排队发送”。
- 原型 `shell.js` 同步改。

配置项、数据库 schema 没有变化。

### 测试

`session-stream.spec.ts` 里运行中有草稿的用例，改成按“排队发送”找按钮。

### 新增依赖

无。

### 已知问题

无。
