# 交付说明：layout

## 2026-11-04　拖动改变侧栏和工作区面板的宽度

> 日期：2026-11-04　PR：见本分支 `feat/shell-resizable-panels`　作者：Claude Code

### 原始需求

用户问“是否有必要支持左右侧栏拖动改变宽度”。结论是做：右侧面板要看 diff 和命令输出，固定 380px 经常截断；左侧栏的会话标题也有同样的问题。这也是同类桌面工具的默认能力，实现不需要新依赖。

原型：[designs/app/shell.js](../../designs/app/shell.js)（手柄 `.k-rz`）、[session.html](../../designs/app/session.html)。

### 怎么验收

1. 鼠标移到左侧栏右边缘，光标变成左右拖动，边缘出现蓝线。拖动，侧栏跟手变宽，范围 200～360px。
2. 会话页拖动右侧面板的左边缘，范围 300～720px。⌘\ 放大工作区后，拖动的是左边对话栏，范围 320～640px。
3. 关掉应用再打开，三个宽度都还在。
4. 双击手柄，恢复默认（248 / 380 / 400px）。
5. Tab 移到手柄上，← → 每次调 16px。
6. 把右侧面板拖到最宽，再把窗口缩到 900px：对话栏至少留 320px，放大工作区时右边至少留 360px；窗口拉大后恢复记住的宽度。
7. 拖动侧栏时不松手，按 ⌘B 收起侧栏，再松手：光标恢复正常，页面文字能选中，收展动画还在。

### 主要改动

- `lib/widths.ts`（新增）：三栏的上下限和默认值，读存储时校验。
- `lib/ui-store.ts`：`widths` 和 `setWidth`，存 localStorage 的 `kits.widths`，和侧栏折叠、面板大小一样按设备记，不进 `settings.json`。
- `ui/ResizeHandle.tsx`（新增）：拖动、双击恢复、键盘调整，`role="separator"`。自身宽度为 0，不占位置。拖动从栏的实际宽度算起，窗口窄时不会有一段拖了没反应。拖动中手柄被卸载时也会清掉全局的拖动状态。
- `Layout`、`Nav`、`SessionPage`：接上手柄，宽度改成 `style`。
- 窗口窄时用 CSS 的 `max-width` 让位，不改记住的值：侧栏不超过窗口 40%，右侧面板给对话留 320px。这也解决了 900px 窗口下对话栏只剩约 270px 的问题。
- 配置项、数据库 schema 都没变。

### 测试

- 单元测试：`widths.test.ts`，上下限、取整、坏数据回退默认。
- E2E：`shell.spec.ts` 拖动、键盘、重开后还在、双击恢复、拖到一半收起侧栏后清掉拖动状态；`workbench.spec.ts` 右侧面板和放大时的对话栏。

### 新增依赖

无。
