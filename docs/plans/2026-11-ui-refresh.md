# 界面改版方案

> 版本：v1　日期：2026-11-05　状态：评审中　原型：`designs/app/`（`session.html`、`shell.js`）

## 要解决什么

用下来发现六个问题：

1. 一次插话后对话里出现两个“第 3 轮”；轮次本身对用户也没有意义。
2. 已有会话的输入框里，工作区和 Agent 改不了却占着位置；权限和模型也是只读的。
3. 侧栏的会话是平铺的，看不出属于哪个工作区。
4. 整体观感（字体、颜色、字号、间距）不够耐看，希望向 DeepSeek Harness 靠拢，背景不必一致。
5. 右侧三个页签里，产出用得少，上下文不值得占一个页签。
6. 没有地方看工作区里的文件。

## 决策

| # | 问题 | 结论 | 理由 |
|---|---|---|---|
| 1 | 轮次 | 界面上不再出现“第 N 轮”。对话里的步骤组只留摘要和耗时，插话前后是两段普通的步骤组，“继续”字样一起去掉 | 两个“第 3 轮”不是 bug：插话把同一轮切成两段，第二段标“继续”。序号本身没有用，去掉后这个问题也没了 |
| 2 | 输入框 | 已有会话不显示工作区和 Agent；权限、模型可改；腾出的位置放上下文用量环 | 改不了的东西不占位置。工作区和 Agent 放在顶栏的路径里，用量是继续聊之前最该看的信息 |
| 2a | 改权限 | 立即生效，这一轮里下一次工具调用起按新权限；已经弹出的确认卡片仍要回答 | 用户调权限通常就是嫌确认太多，等下一条消息才生效没有意义 |
| 2b | 改模型 | 支持，运行中也能选，这一轮不变，下一条消息起生效。内核固定，不能切 | 模型是随每条消息发给内核的，改动小；不支持就只能新开会话、丢掉上下文 |
| 2c | 留痕 | 改权限、改模型都在对话里留一行 | 事后要能知道哪段是哪个模型答的、什么时候放开的权限 |
| 3 | 侧栏 | 按工作区分组，可折叠；组内按最近活动排序，行尾显示相对时间；置顶单独一组放最前；不再有今天 / 昨天分组。按时间看走“全部会话” | 用户按项目想事情。分组方式只做一种，够用就停 |
| 3a | 移除工作区 | 连同其下所有会话记录、附件一起删除，磁盘上的目录和文件不动 | 用户决定。不可恢复，所以要确认，并且写明会删几个会话；有会话在运行时不让移除 |
| 4 | 视觉 | 字体、字号、间距、圆角向 DeepSeek Harness 靠拢；底色保留 kits 略暖的中性灰 | 见“视觉令牌” |
| 5 | 页签 | 右侧只留改动、文件两个常驻页签。上下文进顶栏 `…` 菜单和输入框用量环，以对话框打开 | 上下文是偶尔看的东西 |
| 5a | 产出 | 功能保留，页签去掉。Agent 用 `submit_output` 交了产出，对话里出现一张卡片，点开才在面板加一个可关闭的“产出”页签 | 用例表这类结构化产出是 kits 的主流程，但只有配了产出格式的 Agent 才有。没配的 Agent 不再把回复正文当产出，要留存用“导出会话” |
| 6 | 文件面板 | 右侧新增“文件”页签：目录树 + 只读预览。预览 Markdown、代码、JSON / YAML / XML、CSV、图片、PDF、Word，其余格式给“用系统应用打开” | 测试同学常看需求文档，所以 PDF、Word 算在第一版。xlsx 要再加解析库，这版不做 |

## 各部分设计

原型里能看到全部状态，这里只写原型表达不了的。

### 文案

界面上统一叫“工作区”，不再混用“工作目录”。原来叫“工作区面板”的右侧面板改叫“面板”，免得撞名。代码和配置里的 `workdir` 不改。

### 去掉轮次

- `TurnBlock` 不再渲染标题；`turn.title`、`turn.resumed`、`history.turns` 文案删除。
- 状态胶囊：`运行中 · 0:46`、`已完成 · 3:12`。
- 改动面板原来按轮分组，分组不变，组标题改成这一轮用户消息的第一行。
- 上下文和压缩的文案改成“历史消息”“前面的对话”。“这一轮”不带序号的说法保留，比如“继续这一轮”。
- 数据库的 `turn` 字段不动，内部继续用它分组。

### 改权限和模型

`AgentKernel` 加 `setPermission(session, rules)`，走 `PATCH /session/{id}`。已用 OpenCode 1.19.5 验证：请求体的规则**追加**到会话规则末尾，后面的规则优先，所以把新的完整规则串发过去即可，不需要先清除。CodeAgent 的 SDK 文档写了同样的字段，契约测试跑不了的部分记入核对清单。

- `session.setPermissionMode`、`session.setModel` 两个 IPC，写库后推送会话。`sessionRules()` 本来就按 `session.permissionMode` 算，子会话的自动答复跟着新值走。
- 模型：`runTurn` 每轮从 `session.model` 取，改库即可。正在跑的这一轮用的是开始时的值。
- 换到窗口更小的模型时，已有的上下文接近上限提示（八成）照常出现，不额外拦截。
- 对话里的留痕用新的 part 类型 `notice`。`parts.type` 是文本列，不用迁移。

### 侧栏

工作区列表 = `settings.workdirs` 和所有会话 `workdir` 的并集，按路径规范化后去重，所以旧数据不用迁移。显示名默认取目录名，重命名只改 `settings.workdirs[].label`，不碰磁盘。

- 每组默认显示 5 个会话，多的折成“显示其余 N 个”。折叠状态记在 `ui-store`。
- 当前会话所在的组强制展开；折叠的组里有会话在运行或等处理时，组标题上显示状态点。
- 组标题的 `+` 进首页并预选这个工作区。`…` 菜单：重命名、在访达中显示、移除工作区；右键同一个菜单。
- 移除走一个 IPC `workdir.remove`：先检查没有运行中的会话，再在一个事务里删会话及其消息、附件、产出，最后从设置里移除。内核侧的会话尽力删除，失败不阻塞。
- ⌘K 面板和“全部会话”不变。
- 添加工作区的入口在侧栏“工作区”标题右侧，选目录后写进 `settings.workdirs`。

### 顶栏和 `…` 菜单

顶栏只留：工作区 / 标题、状态胶囊、`…`、面板按钮。Agent 不是默认的 assistant 时跟在工作区后面。内核和模型挪到上下文对话框里（模型在输入框也能看到）。

`…` 菜单：查看上下文、压缩上下文、导出 Markdown、导出 JSON、在访达中显示、重命名、置顶、删除。导出用现有的 `session.export`。原来顶栏的“导出”按钮去掉。

### 产出

`OutputPanel` 的结构化部分保留，挪进可关闭的页签。去掉“回复正文当产出”和空状态。提交产出的步骤和新卡片都打开这个页签；关掉页签不影响数据，从卡片能再打开。

### 文件面板

主进程加三个 IPC，放在 `main/files/`：

| IPC | 作用 | 限制 |
|---|---|---|
| `files.list({ workdir, dir })` | 列一层目录，展开时懒加载 | 跳过 `search.ts` 的 `SKIP` 目录；显示隐藏文件 |
| `files.read({ workdir, path })` | 按类型返回文本、base64 或转好的 HTML | 文本超过 2 MB 截断并标记；二进制超过 20 MB 不读 |
| `files.open({ workdir, path })` | 用系统应用打开 | 走 `PlatformBridge` |

- **路径限制**：三个 IPC 都先 `realpath` 根目录和目标，目标必须在根目录内，符号链接逃出去的一律拒绝。Windows 上比较前规范化大小写和分隔符。
- **渲染**：Markdown 用现有的 `react-markdown`；代码用 shiki；CSV 自己切成表格，只显示前 1000 行；图片用 data URL；PDF 用现有的 `pdfjs-dist` 在渲染进程画 canvas；Word 用现有的 `mammoth` 在主进程转 HTML，放进 `sandbox` 的 iframe，不新增净化库。
- **改动联动**：这个会话改过的文件在树上标 A / M，点了也能看。工具调用结束和回合结束时刷新已展开的目录，再加手动刷新按钮。这版不用 `fs.watch`，大仓库上它不稳定。
- **放大**：窄栏点文件进入预览、有返回按钮；放大后左树右预览，和改动面板一致。
- **引用**：预览工具栏的“引用”把 `@路径` 填进输入框。

## 风险

- **E2E 主流程要改**：`session-status` 文案、产出入口、工作目录选择都变了，放在各自的 PR 里改，不攒到最后。
- **移除工作区不可恢复**：确认框写明会话数，单测覆盖“有运行中的会话时拒绝”和事务回滚。
- **CodeAgent 的 `setPermission`**：只有文档依据，没有实测。行为不一致时退路是 kits 在收到权限请求时按新模式代答，这条路子会话已经在用。
- **规则越积越长**：OpenCode 的会话规则只追加不替换，频繁切换会变长。规则数量很小，暂不处理。
